# Juliet CWE-401 数据集调整：对称插入不可达释放语句（2026-11-23 决定）

## 决定
在**全部** Juliet CWE-401 单元（1,658 组 × bad/good = 3,316 个单元）中，**对称地**插入一条运行时不可达的释放语句（C 用 `free(p)`，C++ 用与分配方式匹配的 `delete p` / `delete[] p`），标签保持不变。
主实验在调整后的数据集上进行。

> **已被取代（2026-11-23）**：见文末“评测分层”。插入只用于第 ③ 层压力测试，主结果用去偏后的原始单元；条件写法改为文件内常量池（见 `PLAN.md` 2.5）。

## 为什么要调整 Juliet
1. **原始数据存在词法捷径。** 规则“函数中没有 `free(`/`delete` 就判为泄漏”不做任何程序分析，在原始全集上 macro-F1 就达到 **0.940**（TP 1461 / FP 0 / TN 1658 / FN 197）。这已经高于 Clang SA（test140 上 0.888）和 CodeQL（0.817）。
   - 1,658 个 good 单元**全部**含 free/delete。
   - 只有 197 个 bad 单元含 free/delete（11.9%）：malloc_realloc 系列 108 个；flow variant 12 共 34 个（一个分支泄漏、另一个分支释放）；variant 82/84 共 54 个（C++ 虚函数 sink、构造/析构）。
   - 按流类别统计 macro-F1：01 为 0.916；02–22 为 0.908；31–45 为 **1.000**；51–68 为 **1.000**；71–84 为 0.869。
2. **这个捷径来自 Juliet 的生成模板，不是抽样偏差。** good 版本（goodG2B/goodB2G）通常就是在 sink 中补上释放，所以扩大数据规模只会让捷径更稳定。对需要训练的方法（decision model 微调），捷径反而更容易被学到。
3. **天花板效应让方法之间分不开。** 原始集上好的方法都挤在 0.93–0.97，Pareto 图纵轴几乎无法区分。
4. **课程相关性。** 不可达释放只能靠路径敏感 / 可达性推理来排除，正好用来检验“是否真的做了程序分析”（对应课程中的数据流、路径敏感性内容）。

## 构造约束
- **对称**：bad 和 good 用同一种插入模板，避免 `if(...) free` 本身变成新的捷径。
- **保持语义**：插入的释放在运行时绝不能执行。在 good 中若可达，就会造成 double free（CWE-415）；在 bad 中若可达，就会改变标签。
- **类型匹配**：C++ 中 `new` 对 `delete`、`new[]` 对 `delete[]`，否则会引入 CWE-762。
- **作用域**：被释放的指针必须在插入点可见（通常是 sink 中的 `data`）。
- **验证**：每个调整后的单元都要重新用 gcc/g++ 编译，并用 ASan/LSan 确认标签不变（bad 仍报泄漏，good 不报，也没有新的 double-free 报告）。动态分析在这里用作标签检验器。
- **之后再做清洗**（`juliet_llm/cleaning.py`），保证 LLM 看到的格式与原流程一致。

## 待定问题
- **不可达条件用哪一种**：
  - `if (globalFalse)` 是 Juliet 自带的非 const 全局变量，静态分析器无法证明它为假，会探索两条路径。在 good 中可能因此触发 double-free 告警，但我们只统计 CWE-401 告警，所以影响可控。在 bad 中，未释放的那条路径仍会被报告。
  - `GLOBAL_CONST_FALSE` 是 extern const，定义在 io.c，单文件分析同样无法知道它的值。
  - `STATIC_CONST_FALSE` 或字面量 `0` 可以被常量折叠，但太容易被词法识别。
  - 倾向：主实验用 `globalFalse`，附录里比较不同条件形式。
  - **已决定（2026-11-23）**：不可达条件从写法池中按固定 seed 随机抽取，bad 和 good 使用同一个池，避免单一模板成为新的捷径。
- **插入位置（已决定，2026-11-23）**：插在 good 中真实释放所在的函数（bad 中对应的同一函数，通常是 sink）；在“指针获得内存之后、函数返回之前”的语句边界中按固定 seed 随机选择；同组 bad/good 用同一相对位置；realloc 类插在 realloc 之后并释放新指针。
- **原始集对照（已决定，2026-11-23）**：在原始集上也运行复杂方法，包括静态分析、动态分析和 LLM-based 方法，并与 grep 基线对比，以说明：在原始 Juliet 上，额外的工作与简单的词法匹配效果相差无几。这个结果作为调整数据集的动机。原始集与调整后数据集上的分数差值作为鲁棒性指标。

## 切分方案（已确认，2026-11-23）
- Juliet 是 family × 流变体的二维网格，任何一维切分都会在另一维上泄漏。family 之间多数只差数据类型，所以按流变体留出更有意义，检验的是“没见过的程序结构”。
- 比例按课程指南 Juliet 示例的 dev/test = 20/80。
- 规则：以流变体为分配单位；dev 名额 02–22: 4、31–45: 2、51–68: 2、71–84: 1，01 不进 dev；候选必须含 C++ new，02–22 候选还须含 realloc 失败类；01 与 12 强制留在评测集；seed 20261123。
- 脚本 `juliet/scripts/split_full.py`，清单 `juliet/full_split_v1.json`（SHA-256 `08017a6f8088bdf103642ce9f829209c62adea329f380cac16ac4d75deed0065`，可复现）。
- **冻结开发集**：流变体 04 10 17 18 31 41 65 68 73，共 330 组 / 660 单元（19.9%）；用于 prompt 设计、few-shot 示例池、阈值、调试和超参数，结果不报告，每轮可并入训练。
- **评测集**：其余 39 个流变体，1,328 组 / 2,656 单元。零样本方法全量运行；需要训练的方法（目前只有 decision model 微调；LineVul 只作为原版零样本基线，不再微调）按 3 折分组交叉验证（两折 + dev 训练，约 1,215 组），每个单元恰好得到一次预测。

## 报告粒度（建议）
- 任务和主结果统一为 **CWE-401 二分类**（leak / no leak），只报告一个总体数字。family 不作为结果类别展示。
- family 只用于数据切分和聚类 bootstrap。
- 细分维度一：5 个**流类别**（01 / 02–22 / 31–45 / 51–68 / 71–84），对应课程中的程序分析概念。
- 细分维度二（可选）：4 个**分配机制**，把 42 个 family 合并：
  - C 分配器 malloc/calloc/realloc/strdup：20 个 family，960 组；
  - malloc_realloc（realloc 失败时原指针泄漏）：6 个 family，108 组；
  - C++ new/new[]：14 个 family，588 组；
  - destructor / virtual_destructor：2 个 family，2 组。
- 注意：很多 family 只是数据类型不同（char/int/wchar_t…），代码几乎一样。纯按 family 切分仍会出现跨集近重复。（已解决：改为按流变体留出，见“切分方案”。）
- **残余捷径（重要）**：只插入一种 `if (globalFalse) free(p);` 后，bad 只含“带守卫的 free”，good 还多一个“无守卫的 free”。词法模型可以改学“有无守卫 free”这条新捷径。缓解办法：守卫从多种形式中随机抽取（全局变量、函数返回值、需要常量传播的局部表达式等），bad/good 用同一个形式池；或者 good 中的真实 free 也随机包上恒真守卫。之后用词袋探针检验。
- **残余捷径探针**：用词袋逻辑回归作为基线，检查调整后是否还有其他词法线索。

## 新发现：现有清洗单元存在 `static void` 结构捷径（2026-11-23）
- 在 `juliet_llm/build/{dev,test}.jsonl`（200 单元）中，good 单元 100/100 含 `static void`，bad 单元 0/100 含；单条规则“含 `static void` → good”准确率 100%。
- 原因：Juliet 的 good 部分由 `static void goodG2B()`、`static void goodB2G()` 和包装函数 `void ..._good() { goodG2B(); goodB2G(); }` 组成，bad 只有一个非 static 函数。函数个数也不同：good 87% 含 ≥3 个函数定义，bad 21%。
- 文献已报告同类偏差：Germano et al., "Evaluating Biased Synthetic Data Effects on LLM-Based Software Vulnerability Detection", ICAART 2025（`static void` 在 99.7% 非漏洞文件中出现、漏洞文件 8.3%；"cascade" 包装函数 99.6% vs 0.01%）。
- 影响：此前 Juliet LLM 结果（如 MiMo L1 0.95）可能部分来自这一捷径。
- 待定：单元构造需去除该结构差异（例如每个 good 单元只保留一个入口函数并去掉 `static` 与包装函数）。

## 评测分层（已决定，2026-11-23）
- 三层：①主结果 = 原始 CWE-401 去除格式偏差（`static void`、包装函数），不改程序逻辑；②天然难例子集 = 主结果评测集的子集过滤，不修改代码；③压力测试 = 不可达 free 插入 + good 真 free 包入恒真条件 + free 个数分布一致，另配不含 free 的安慰剂插入对照。
- 不可达 free 插入只用于第 ③ 层（取代“所有单元都插入”的早期决定）；原始集与 grep 对照保留在第 ① 层。
- 三层与切分正交：切分清单 `juliet/full_split_v1.json` 按组划分不变，各层只是同一组的不同版本。

## good 单元构造（已决定，2026-11-23，需写入 plan）
- 每组只构造 1 个 good 单元：从该组所有 good 入口函数（goodG2B、goodB2G 及其编号版本，如 goodG2B1/goodG2B2）中按固定 seed 抽取一个；在每个流类别内分层，使 G2B 与 B2G 约各占一半。
- 去掉 `static` 与包装函数 `..._good()`，保留所抽函数用到的 Source/Sink 辅助函数；bad 单元只保留 `bad()` 及其辅助函数。
- bad:good 保持 1:1；“good 类型（G2B / B2G）”作为细分维度报告。
- 训练类方法只用第 ① 层（原版去偏）数据训练；压力测试版与安慰剂版只用于预测。
